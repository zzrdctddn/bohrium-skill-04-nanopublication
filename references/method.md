# ACEB 方法细则与反例库

## 一、四道工序不可合并
拆解（A）→ 绑定（C）→ 溯源（E）→ 导出（B）是四道独立工序。拆解阶段只管"一个命题一条断言"，绑定阶段才找证据，核验阶段以审阅者身份独立回扫。禁止一边拆一边自我判定"这条肯定对"，否则会把错误限定与错误证据一起固化。

## 二、机制 A：原子断言拆解细则
一条合格原子断言须同时满足：
- **单命题**：只含一个可独立判断真假的核心命题；复合句按并列/因果/转折拆开。
- **保留限定**：条件（在 X 下）、范围（在 Y 样本中）、限定词（约/仅/显著/可能）、否定与量词（所有/部分）原样保留，不加强也不削弱。
- **主体明确**：主体是材料里真实出现的对象，不用常识补一个更"专业"的主体。
- **判据**：问自己"这条断言能否被单独判定为真或假？"不能则继续拆。

反例：把"方法 A 在数据集 D 上准确率 90%，且显著优于基线 B"塞成一条 → 含"准确率 90%"和"优于基线"两个判真点，应拆两条。

## 三、机制 C：证据绑定细则
- **最小充分**：证据片段是能支撑该断言的最短连续原文——去掉任何一句就不够支撑，加上任何一句都冗余。
- **位置精确**：标到段落 ID/章节/图表号/公式号；线性化的行内公式保留原文形态。
- **直接 vs 间接**：`direct` = 原文直接陈述该断言；`indirect` = 需跨句推断或由其他事实推出。间接必须标注，不冒充直接证据。
- **无支撑不写事实**：找不到支撑片段 → `unsupported`，进 `human_review_items`。

## 四、机制 E：来源链路细则
每条断言-证据单元都要能回答"谁的、哪篇、哪年、哪个版本、从哪来、唯一标识是什么"。跨论文/跨版本不得混用元数据；缺项标 `unverified` 而非臆造。位置是组织方段落 ID，不是自建 PDF 页码。

## 五、机制 B：受控字段导出细则
字段名、类型、标识符规则一律以 `nanopub_fields.md` 为准；关系类型用受控词表，不在词表时用 `other` + 原文表述。导出后用 `node -e "JSON.parse(require('fs').readFileSync('result.json','utf8'))"` 校验。

## 六、反例库
| 反例 | 为什么错 | 改法 |
|---|---|---|
| 把整段摘要塞进一个"断言"字段 | 一段含多个可独立判真点，无法逐条判真 | 按单命题拆成多条 `claim_id` |
| "模型效果很好" | 无主体、无量词、限定丢失 | 补回主体/条件/数值/限定词 |
| 证据片段取整个摘要 | 不最小充分，他人无法定位支撑句 | 缩到最短连续支撑句并标位置 |
| 把"可能相关"写成"导致" | 间接推论冒充直接因果，加强结论 | 标 `indirect`，保留"可能/相关"原文措辞 |
| 主体张冠李戴（把对比方法当本文方法） | 关系方向/主体错，断言失真 | 核对原文主体，修正并记 change_log |
| 第二篇论文套用第一篇 DOI/作者 | 跨论文元数据混用 | 逐篇独立登记来源，缺项标 unverified |
| 把自建"第1页"写成原 PDF 页码 | 位置造假，无法回原文 | 用材料给出的段落 ID |
| 自定义字段名 `myClaim` 导出 | 下游无法解析 | 改用受控字段 `claim`/`evidence`/`provenance` |

## 七、拆解与核验分离
起草阶段禁止自我核对；完成后以"审阅者"身份执行 checklist 与 `quality_check`（断言过宽/证据不足/关系错误/主体混淆/来源缺失），每次改动写 change_log。材料缺失、无法判断、运行失败分别说明，不编造事实与 benchmark 分数。
